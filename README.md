# claim-audit-agent（要項監査エージェント）

一般の募集要項・規約・FAQ を読み、要件を「要項から引用したもの」と「推測」に分けて構造化し、提出物を実際に検査して、確かめた結果つきで判定を返す**読み取り専用**のエージェントです。

- 要件は、要項の1文を**逐語照合できたもの**だけを「引用つきの要件」として扱います。照合できなかったものは推測に落とし、画面でも区別して出します。
- 提出物には HTTP での到達検査・ログイン壁の検出・字数の計測・漏洩の走査などを、決まった手順（コード）で当てます。
- 適合・不適合などの**判定は、確かめた結果からコード（`app/adjudicate.py`）だけが決めます**。AI（モデル）は判定を書けません。確かめる根拠が無いものは「確認不能」（理由コードつき）になります。
- 提出物にも要項にも書き込みません。外向きは GET/HEAD 相当の取得だけです。
- 結果の画面には、判定のほかに、要項から取り出した要件の一覧（種別・引用・出典）の帯があります（最初は閉じています）。画面に届いた実行の記録だけで組み、サーバーも Reader も変えていません。保存済みの実行では最大40件・引用は80字までと注記します。Markdown の一括コピーは、架空の例（②③）だけに出します（実在の主催者の要項は画面で見せるだけ）。

## 統制（暴走・乗っ取りを抑える仕組み）

- **許可リスト**: 取得してよい先は、プリセットで固定した URL の接頭辞だけ。公開面の入力はプリセット ID だけで、既定では任意の URL は受けません（例外は下の「GitHub の公開リポジトリの基本点検」で、環境変数で有効にした審査員コード専用の入口だけです）。Planner は URL を渡せず、リンク表の ID だけで指します。
- **ツールは5本だけ**: `fetch_link`・`http_probe`・`run_check`・`mark_unverifiable`・`finish`。モデルが出した関数呼び出しは、1つずつ Governor が許可／拒否します（拒否は必ず理由コードとともにトレースへ残ります）。
- **上限**: モデル呼び出し数・トークン・ツール呼び出し数・取得数・第三者ホスト数・要件ごとの回数・壁時計・拒否の連続回数に上限があり、到達すると理由つきで部分結果を返して止まります。
- **SSRF 遮断**: 外向き HTTP は SafeFetch だけ。私的・予約済みアドレス、リダイレクト先の再検査、受信量とヘッダの上限、接続先のピン留めを行います。
- **注入の扱い**: 取得物は非信頼として洗浄し、プロンプトインジェクションの疑いのある区間は読み取りモデルへ渡す前に伏せます。提出物の隠しテキストはどのモデルにも渡しません。Planner が見るのは ID・種別・数値だけの状態（自由文を持たない型）です。
- **AUTORUN（検査の取りこぼしを作らない）**: 要項を読んだ後、前提がコードで判定できる検査（提出URLの到達検査・ログイン壁・字数・漏洩・実行環境の署名・語の有無）を、モデルの手を待たずに必ず走らせます。Planner と router は同じ AUTORUN の後に動き、AUTORUN で決まらなかった要件だけを扱います。各手は Governor の許可・予算・トレース（tool_request／tool_result）を通ります。Reader の「検査を減らす」方向の提案（ページ種別・必須→任意・login の役割）は、コードの値と一致した時だけ採ります。
- **Planner の出番は残りだけ**: Planner（モデル）が扱うのは、AUTORUN で決まらなかった要件だけです。決めることが残っていなければモデルを呼ばずに終え（費用0。トレースに `autorun/planner_skipped`）、手順（routes）は状態に応じて更新されます。案内の有無が不確定なら、案内ページを辿る手になります。画面の「誰が決めたか」の帯は、この内訳（AUTORUN が実行した検査・Planner が判断した手・方針変更・モデル呼び出し・見積もり費用）を記録から数えて出します。
- **語の有無 `contains_terms`**: 語は check_class ごとの固定辞書（コード定数）で、モデルも要件の文章も語を決めません。見るのは可視テキストだけ（HTML コメント・隠しテキストは数えない）。注入疑いの区間は命中に数えず、そういう文書では「無い」を結論にしません。「無い」を不適合にするかは判定表が、文書の完全性と要件の種別で決めます。提出物の説明に無い時は、案内ページへのリンクを辿ってから確かめます（辿る前に AUTORUN が「無い」を確定させないため、案内ページが残る間は AUTORUN がこの検査を後回しにします）。
- **方針変更の記録**: 検査が不確定だった直後に、Planner が別のページを取りに行く手を取ると、コードが `replan` の印をトレースに残します（モデルの申告ではなく、観測と許可された呼び出しの並びから決めます）。画面の「判断が変わった場面」はこの印を読みます。公開のプリセット②（架空サンプル）の同梱 REPLAY には、この場面（案内の有無を確かめ、無いので案内ページを辿り、辿った先で再確認）が入っています。同梱の記録は決定論の規則（`RulePlanner`・記録の planner_model は `rule-planner`）で作ったもので、実モデルの実行ではありません。
- **判定はコードが出す**: 判定を書けるのは `app/adjudicate.py` だけ。「検証済み」の印を発行できるのは `app/quotes` だけです（どちらもテストで固定しています）。
- **キルスイッチ**: 環境変数 `KILL_SWITCH=1` で、実行中も含めて全モデル呼び出しを止めます。
- **REPLAY 降格**: キルスイッチ・枠切れ・停止中・保存先の障害のときは、ライブ実行をせず同梱の実行記録の再生に落とします（画面にも REPLAY と理由を表示）。
- **時間切れの切り替え**: 1回のライブ実行の壁時計の上限は100秒です（Cloud Run の timeout は120秒）。モデルの応答が遅い時間帯に上限へ当たった時は、判定のない中断の画面を出さず、保存済みの実行を最初から再生します（理由 `LIVE_TIMEOUT` を画面に表示）。モデル呼び出しは壁時計の締切＋2秒までで打ち切る（`app/model/wallbound.py`）ので、中断は実際に使った費用で精算されます。
- **同梱の記録は要項の文を短くして持つ**: 実行記録を同梱するときは、引用などの要項の断片を1件80字までに切り詰め（`quote_clipped`）、要件は40件までにします。同梱の記録は要項の全文を持たないため、再生時に引用の再検証はせず、「保存時に検証済み」と表示します。
- **GitHub の公開リポジトリの基本点検（審査員コード専用・既定オフ）**: 環境変数 `GITHUB_INPUT_ENABLED=1`（S2。`JUDGE_CODE_SHA256` も必要）の時だけ、`POST /api/run` が `{"preset_id": "github_repo", "repo_url": "https://github.com/<owner>/<repo>"}` も受けます。審査員コード（`X-Judge`）が無い・合わない時は拒否し、匿名の枠は使いません。取得は固定名のファイル（README・LICENSE・Dockerfile・requirements.txt）だけで、トークンは預かりません。点検はコードだけが決める固定3項目（ライセンスの表示・READMEに公開してはいけない情報が無いか・必須技術の痕跡）で、**モデルは呼ばず、READMEなどの中身はモデルに渡しません**。要項の要件には結びつけず、結果の型 `RepoAuditResult` は自由文を持てません（理由は固定文、証拠は識別子・種類名・件数だけ）。ライセンスは語句の判定で全文の照合ではない（改変した文を見分けられない）ため、確信できても「推定適合」までで「適合」は出しません。取れなかった項目は「適合」と言わず確認不能にします。S3 側は別に `GITHUB_RAW_ENABLED=1` が要り、無い時は「いま使えません」の固定文を返します。
  - **今後（今回は未実装）**: Planner がファイルを選ぶ形／点検結果の要項の要件への結びつけ／固定4種類以外のファイル（サブディレクトリの README など）の取得。
- **要項モード（第11弾。審査員コード専用・既定オフ）**: 環境変数 `SPEC_INPUT_ENABLED=1`（S2。`JUDGE_CODE_SHA256` も必要）の時だけ、`POST /api/run` が `{"preset_id": "spec_url", "spec_url": "https://…"}` も受けます。受けるのは `https://` の公開ホスト名の URL だけです（ポートの指定・userinfo・IP アドレスの直書き・localhost・単一ラベル・`.local`／`.internal` など・フラグメントは拒否。入力の URL は応答にもログにも出さず、ログは sha256 の先頭12桁だけ）。審査員コードが無い・合わない時は拒否し、匿名の枠は使いません。ページは1ページだけ取り、リンクは辿りません。取得したページは既存の洗浄（隠しテキストの分離・プロンプトインジェクションの疑いの区間を伏せる）を通して **Reader だけ**にかけ、引用を要項の文と照合した**要件の一覧（種別・根拠の一文・出典）だけ**を返します。Planner・AUTORUN・検査・判定は動かしません（結果の型 `SpecOnlyRecord` は `kind: "spec_only"` で、判定・観測・矛盾を持てません）。Reader を呼ぶので、審査員の枠を使い実費で精算します。S3 側は別に `SPEC_FETCH_ENABLED=1` が要り（`contracts.OpenPageScope`。既定は無効）、転送は追わず、200 の text/html と text/plain だけ・本文 1MiB まで・私的アドレスは名前解決後に拒否、窓あたりの件数でも頭打ちにします。S3 が拒否した時は「いま使えません」の固定文を返します。
  - **複数リンク（上限3件）**: `{"preset_id": "spec_url", "spec_urls": ["https://…", …]}`（1〜3件。`spec_url` の1件の形も受けますが、どちらか一方だけ。両方・0件・4件以上・重複・型違いは拒否）。各 URL を1ページずつ取り（リンクは辿らない）、取れたページを出典 D1〜D3 の文書として Reader に渡します。取れない・形式が違うページはそのページだけを飛ばし、結果の `skipped_pages` に「何番目か・理由の種類（固定文）」だけを載せます（URL は載せない）。全部取れなければ固定文のエラーです。費用は1実行の既存の上限のままで、超えたら部分結果（DEGRADED）になります。`/api/status` の `spec_url` には `"max_urls": 3` が付きます。

### 手元で、別の要項を検査する（事実と条件）

公開デモ（S2）は、用意した3つの対象だけを選べます。任意の URL は受け付けず、環境変数も固定です。手元で起動する時は、次の2つで、プリセット①の対象を差し替えられます。

| 環境変数 | 意味 | 条件 |
|---|---|---|
| `LP_SEED_URLS` | 要項のページの URL（カンマ区切り） | 最大3件。**URL の完全一致**だけを取得します（同じホストの別のページは取りません）。4件以上は拒否します。HTML だけで、PDF は読めません |
| `SELF_ORIGIN` | 検査する提出物のサイトの origin（`https://` だけ） | 調べるのは、その最上位のページ `/` だけです。`SUBMISSION_URL` を置く時も、`SELF_ORIGIN` の最上位か `/fx/` の中だけ（別のホスト・別のパスは、起動時に拒否します） |

- 実行は `python -m app.cli lp_self --inspect-mode planner`（Google Cloud の認証設定が要ります）。
