# claim-audit-agent（要項監査エージェント）

一般の募集要項・規約・FAQ を読み、要件を「原文の引用」と「推測」に分けて構造化し、提出物を実際に検査して、証拠つきで合否を返す**読み取り専用**のエージェントです。

- 要件は、原文の1文を**逐語照合できたもの**だけを「引用つきの要件」として扱います。照合できなかったものは推測に落とし、画面でも区別して出します。
- 提出物には HTTP での到達検査・ログイン壁の検出・字数の計測・漏洩の走査などを、決まった手順（コード）で当てます。
- 適合・不適合などの**判定は、観測からコード（`app/adjudicate.py`）だけが決めます**。モデルは判定を書けません。証拠が無いものは「確認不能」（理由コードつき）になります。
- 提出物にも要項にも書き込みません。外向きは GET/HEAD 相当の取得だけです。

## 統制（暴走・乗っ取りを抑える仕組み）

- **許可リスト**: 取得してよい先は、プリセットで固定した URL の接頭辞だけ。公開面の入力はプリセット ID だけで、任意の URL は受けません。Planner は URL を渡せず、リンク表の ID だけで指します。
- **ツールは5本だけ**: `fetch_link`・`http_probe`・`run_check`・`mark_unverifiable`・`finish`。モデルが出した関数呼び出しは、1つずつ Governor が許可／拒否します（拒否は必ず理由コードとともにトレースへ残ります）。
- **上限**: モデル呼び出し数・トークン・ツール呼び出し数・取得数・第三者ホスト数・要件ごとの回数・壁時計・拒否の連続回数に上限があり、到達すると理由つきで部分結果を返して止まります。
- **SSRF 遮断**: 外向き HTTP は SafeFetch だけ。私的・予約済みアドレス、リダイレクト先の再検査、受信量とヘッダの上限、接続先のピン留めを行います。
- **注入の扱い**: 取得物は非信頼として洗浄し、偽の命令の疑いのある区間は読み取りモデルへ渡す前に伏せます。提出物の隠しテキストはどのモデルにも渡しません。Planner が見るのは ID・種別・数値だけの状態（自由文を持たない型）です。
- **AUTORUN（検査の取りこぼしを作らない）**: 要項を読んだ後、前提がコードで判定できる検査（提出URLの到達検査・ログイン壁・字数・漏洩・実行環境の署名・語の有無）を、モデルの手を待たずに必ず走らせます。Planner と router は同じ AUTORUN の後に動き、AUTORUN で決まらなかった要件だけを扱います。各手は Governor の許可・予算・トレース（tool_request／tool_result）を通ります。Reader の「検査を減らす」方向の提案（ページ種別・必須→任意・login の役割）は、コードの値と一致した時だけ採ります。
- **Planner の出番は残りだけ**: Planner（モデル）が扱うのは、AUTORUN で決まらなかった要件だけです。決めることが残っていなければモデルを呼ばずに終え（費用0。トレースに `autorun/planner_skipped`）、手順（routes）は状態に応じて更新されます。案内の有無が不確定なら、案内ページを辿る手になります。画面の「誰が決めたか」の帯は、この内訳（AUTORUN が実行した検査・Planner が判断した手・方針変更・モデル呼び出し・見積もり費用）を記録から数えて出します。
- **語の有無 `contains_terms`**: 語は check_class ごとの固定辞書（コード定数）で、モデルも要件の文章も語を決めません。見るのは可視テキストだけ（HTML コメント・隠しテキストは数えない）。注入疑いの区間は命中に数えず、そういう文書では「無い」を結論にしません。「無い」を不適合にするかは判定表が、文書の完全性と要件の種別で決めます。提出物の説明に無い時は、案内ページへのリンクを辿ってから確かめます（辿る前に AUTORUN が「無い」を確定させないため、案内ページが残る間は AUTORUN がこの検査を後回しにします）。
- **方針変更の記録**: 検査が不確定だった直後に、Planner が別のページを取りに行く手を取ると、コードが `replan` の印をトレースに残します（モデルの申告ではなく、観測と許可された呼び出しの並びから決めます）。画面の「判断が変わった場面」はこの印を読みます。公開のプリセット②（架空サンプル）の同梱 REPLAY には、この場面（案内の有無を確かめ、無いので案内ページを辿り、辿った先で再確認）が入っています。同梱の記録は決定論の規則（`RulePlanner`・記録の planner_model は `rule-planner`）で作ったもので、実モデルの実行ではありません。
- **判定はコードが出す**: 判定を書けるのは `app/adjudicate.py` だけ。「検証済み」の印を発行できるのは `app/quotes` だけです（どちらもテストで固定しています）。
- **キルスイッチ**: 環境変数 `KILL_SWITCH=1` で、実行中も含めて全モデル呼び出しを止めます。
- **REPLAY 降格**: キルスイッチ・枠切れ・停止中・保存先の障害のときは、ライブ実行をせず同梱の実行記録の再生に落とします（画面にも REPLAY と理由を表示）。
- **同梱の記録は原文を短くして持つ**: 実行記録を同梱するときは、引用などの原文の断片を1件80字までに切り詰め（`quote_clipped`）、要件は40件までにします。同梱の記録は原文を持たないため、再生時に引用の再検証はせず、「保存時に検証済み」と表示します。

## テストの実行（完全オフライン）

```bash
pip install -r requirements-dev.txt
python -m pytest
```

外向き通信は `tests/conftest.py` が遮断します。モデルは台本（`ScriptedPort`）、取得は偽の `FetchPort` で置き換えており、Vertex・gcloud・Firestore の実物は使いません。
全テストは Python 3.13（`Dockerfile` と同じ系列）と 3.14 の両方で通ることを確認しています。標準ライブラリの版差で結果が変わる部分（`idna` による IDN ホスト名の変換、`html.parser` のコメントの解釈）は、版に依らない形で固定し、どちらの版でも同じ結論（開けない・拒否）になるようにしています。`xfail` が数件あります（`tests/test_sanitize_adversarial.py` の既知の残り＝HTML 解析の近似の限界）。

## 測定の道具（実モデルは `--live` を付けた時だけ呼びます）

```bash
python -m app.fixtures.eval                 # 欠陥の変種 × {Planner, router} の表（ツール呼び出し・誤った absent・確認不能・トークン・推定費用）。Markdown と JSON
python -m app.fixtures.eval --live          # 実モデル（Vertex。認証は ADC）で測る。呼び出し回数の上限は既定 40（最大 120。再試行も数える）
python -m app.fixtures.baseline             # 注入耐性の対照: 素朴なエージェントと本作に、偽の命令入りフィクスチャを N 回ずつ当てる
python -m app.fixtures.baseline --live      # 同じ。実モデルで
```

- 既定はオフラインで、モデルを呼びません。オフラインの Planner は規則で動く `RulePlanner`（案内ページを辿る）、Reader は台本で、トークンと費用は台本が数えた見積もり（表の `*`）です。実モデルの結果ではありません。
- 注入耐性の対照のオフライン版は、「偽の命令に従うモデル（最悪の想定）」を当てた時にどこで止まるかの構造の確認です。どの実モデルが従うかは `--live` で測ります。取得はすべて `FetchPort` を通り、取得先はフィクスチャ内の架空の誘導先（`*.invalid`）だけで、外へは出ません。
- 結果は測ったとおりに出します（良く見せる処理は入れていません）。

## ローカルでの実行

- 公開面: `python -m app.web`（`ROLE=fetcher` なら fetcher）。`LIVE_ENABLED=1` でライブ実行、無ければ同梱の REPLAY を返します。
- CLI: `python -m app.cli <preset> [--inspect-mode planner|router] [--format json|html]`（実モデルの呼び出しには Google Cloud の認証設定が要ります）。
- 架空フィクスチャ: `python -m app.fixtures.gen --check`、評価は `python -m app.fixtures.eval`（モデル不使用）。
- 実行記録の取り込み: `python -m app.web.replay --import rec.json --preset <id>`（漏洩の走査・原文の切り詰め・契約の検証を通ったものだけ）。

デプロイの手順は `deploy.sh`（既定は表示だけ。`--apply` で初めて実行）にあります。URL や設定値はこのリポジトリには書きません。
